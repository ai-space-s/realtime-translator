# Between — 설교·강의용 실시간 번역 자막

브라우저의 마이크 또는 오디오 인터페이스 입력을 받아 다른 언어의 자막으로 표시하는 로컬 웹앱입니다. 운영자는 원문·번역을 확인하고, 같은 PC의 프로젝터·보조 모니터에는 별도 청중용 창을 띄웁니다.

## 주요 기능

| 통역 방식 | 서비스 | 용도 |
| --- | --- | --- |
| 빠른 통역 · 기존 방식 | OpenAI / Microsoft Azure / Google | 사전 원고 없이 실시간 번역 자막 표시 |
| 설교 정확도 · 원고·사전 참고 | OpenAI | 설교 원고, 발표자 사전, 성경 인용문을 참고한 통역 |
| 세미나-원고제공방식 | OpenAI | PDF·텍스트 원고를 구간별로 검토하고 수동 위치 지정·자동 추적·질의응답으로 운영 |

원어·번역어 병기, 별도 청중 자막 창, Markdown 통역 기록 내보내기를 제공합니다. 세미나 원고와 용어집은 JSON으로 저장해 재사용합니다. **API 키 없는 데모는 화면 확인용이며, 실제 통역에는 해당 서비스의 API 키·접근 권한·인터넷 연결이 필요하고 비용이 발생할 수 있습니다.**

## 실행

Node.js 22.14 이상이 필요합니다.

처음 사용하는 경우 Git으로 저장소를 내려받습니다. GitHub의 **Code → Download ZIP**으로 받은 경우에는 압축을 풀고 해당 폴더에서 다음 설치 단계를 진행하세요.

```powershell
git clone https://github.com/ai-space-s/realtime-translator.git
cd realtime-translator
```

아래 예시는 Windows PowerShell 기준입니다. macOS/Linux에서는 `.env.example`을 `.env`로 복사할 때 `cp .env.example .env`를 사용합니다(처음 설정할 때만 실행).

```powershell
npm ci
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
# .env에 사용할 서비스의 키를 입력합니다.
npm run dev
```

[로컬 앱 열기](http://localhost:5173). API 키 없이 **마이크 없이 데모 체험**으로 자막 동작을 확인할 수 있습니다. 데모는 준비된 4개 발화(여러 문장)를 재생하며, 실제 음성 인식·번역·API 호출은 하지 않습니다.

배포용 빌드와 로컬 실행:

```powershell
npm run build
npm start
```

## 추가 언어 지원 — 라오어·인도네시아어

한국어 음성을 라오어 또는 인도네시아어(Bahasa Indonesia) 자막으로 표시할 수 있습니다. 아래 표는 **현재 앱의 빠른 통역 경로** 기준이며, 실제 계정의 연결 성공이나 번역 품질을 보장하는 표는 아닙니다.

| 번역 언어 선택 항목 | 언어 코드 / 로케일 | OpenAI 빠른 통역 | Microsoft Azure Speech | Google Live Translate |
| --- | --- | --- | --- | --- |
| 라오어 (라오스) | `lo` / `lo-LA` | 사용 불가 · 선택 시 안내/차단 | 사용 가능 | 사용 가능 |
| 인도네시아어 (Bahasa Indonesia) | `id` / `id-ID` | 사용 가능 | 사용 가능 | 사용 가능 |

두 언어 모두 기존 **이전·현재 자막(각 최대 3문장)**, **번역어만 / 원어 + 번역어**, **Markdown 기록 내보내기**, **마이크 없는 고정 데모**를 이용합니다. 선택한 서비스의 기존 API 키를 사용하며, 언어별로 새 키를 발급받을 필요는 없습니다. 원고·설교자 사전 참고는 빠른 통역에 적용되지 않으며, 정확도 모드의 지원 범위와 제한은 아래 안내를 확인하세요.

### 한국어 → 인도네시아어(Bahasa Indonesia) 자막

1. **OpenAI Realtime**, **Microsoft Azure Speech**, **Google Live Translate** 중 설정한 서비스를 선택합니다. OpenAI에서는 **빠른 통역 · 기존 방식**으로 사용할 수 있습니다.
2. 말하는 언어를 **한국어**, 번역 언어를 **인도네시아어**로 선택합니다. 선택란 아래에 Bahasa Indonesia 안내가 표시됩니다.
3. 통역을 시작하면 기존 이전·현재 자막에 인도네시아어가 표시됩니다. ‘원어 + 번역어’ 병기와 기록 내보내기도 지원합니다. 먼저 ‘마이크 없이 데모 체험’으로 고정 예문의 표시를 확인할 수 있습니다.

인도네시아어 코드는 `id`, 로케일은 `id-ID`입니다. 언어 추가에는 새 API 키가 필요하지 않습니다. 설교자 사전의 언어 선택·JSON 가져오기/내보내기에도 인도네시아어가 포함됩니다. 사전 참고는 OpenAI 정확도·세미나 모드에서 사용할 수 있습니다. 후속 세미나 구현에서 기존 음성 인식 VAD 설정을 공식 문서에 맞춰 수정했으며, 실제 마이크·유료 API의 연결·번역 품질 검증은 별도로 필요합니다. [검증 기록](VERIFICATION.md)을 참고하세요.

2026-10-11 공식 문서의 [OpenAI Realtime Translation 출력 언어](https://developers.openai.com/cookbook/examples/voice_solutions/realtime_translation_guide#supported-languages), [Azure Speech 번역 대상 언어](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support?tabs=speech-translation#real-time-speech-translation), [Google Live Translate 지원 언어](https://ai.google.dev/gemini-api/docs/live-api/live-translate#supported-languages)에 Indonesian이 포함됩니다. 실제 계정 접근 권한과 설교 번역 품질은 별도 확인이 필요합니다. 고정 데모와 모의 API 테스트는 실제 번역 품질을 보장하지 않습니다.

업데이트 후 서버를 재시작하고, 보관할 기록·입력 자료를 저장한 뒤 운영자·청중 창을 새로고침하세요. 현장 사용 전 인도네시아어 화자와 성경 인명·장절, 부정 표현, 숫자와 즉흥 발언을 점검하세요.

### 한국어 → 라오어 자막

1. **Microsoft Azure Speech** 또는 **Google Live Translate**를 선택하고 해당 서비스의 키를 설정합니다. 기존 키 설정 방식은 그대로입니다.
2. 말하는 언어를 **한국어**, 번역 언어를 **라오어 (라오스)**로 선택합니다.
3. 통역을 시작하면 기존 이전·현재 자막 영역에 라오어가 표시됩니다. ‘원어 + 번역어’를 선택하면 한국어도 함께 표시합니다. 기록 내보내기에도 라오 문자를 유지합니다.

라오어 코드는 `lo`, 로케일은 `lo-LA`입니다. 라오어 글꼴과 결합 문자를 보존하는 고정 데모 예문도 추가했습니다. 데모는 레이아웃 확인용이며 실제 번역 품질의 근거가 아닙니다. 인터넷 글꼴 로드 실패 시 운영체제의 라오어 글꼴을 사용합니다.

2026-10-11 공식 문서 기준 [Azure Speech 번역 대상 언어](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support?tabs=speech-translation#real-time-speech-translation)와 [Google Live Translate 지원 언어](https://ai.google.dev/gemini-api/docs/live-api/live-translate#supported-languages)에 Lao가 포함됩니다. [OpenAI Realtime Translation의 출력 언어](https://developers.openai.com/cookbook/examples/voice_solutions/realtime_translation_guide#supported-languages)에는 Lao가 없습니다. 이번 버전에서는 **OpenAI의 빠른 통역·설교 정확도 모드 모두 라오어 경로를 활성화하지 않으며**, 선택 시 안내하고 마이크 시작/외부 요청을 차단합니다. 다른 서비스나 유료 모드로 자동 전환하지 않습니다. 원고·설교자 사전 참고는 기존 OpenAI 전용 기능이므로 Microsoft/Google 라오어 통역에는 적용되지 않습니다.

업데이트 후 서버를 재시작하고, 보관할 기록·입력 자료를 저장한 뒤 운영자·청중 창을 새로고침하세요. 현장 사용 전 라오어 화자와 대표 설교를 점검하세요. 특히 성경 인명·장절, 부정 표현, 숫자와 즉흥 발언의 보존을 확인해야 합니다. 실제 음성/API 품질·계정 접근 권한은 자동 테스트로 검증하지 않았습니다.

## 서비스 설정

`.env`에 OpenAI, Microsoft Azure, Google 중 사용할 서비스의 키를 설정합니다. 하나만 설정해도 사용할 수 있습니다. 키를 클라이언트 코드나 `VITE_` 환경변수에 넣지 마세요. 화면의 ‘설정됨’은 입력 여부만 나타내며 실제 서비스 접근 가능 여부는 시작할 때 확인합니다.

서비스 키·리전·통역 모델은 프로젝트 `.env` 값을 실행 환경보다 우선하여 읽습니다. 변경 후 연결 설정의 ‘설정 다시 확인’을 누르면 재시작 없이 다음 연결에 반영됩니다. 키가 있는 서비스가 하나뿐이면 자동 선택합니다. 변수 이름은 `OPEN_API_KEY`가 아닌 `OPENAI_API_KEY`입니다. 포트·호스트 변경 또는 서버 코드 변경 시에는 서버를 재시작하세요. 실제 키는 `.env`에만 넣고 `.env.example`에는 넣지 마세요.

| 공급자 | 필요한 설정 | 구현 방식 |
| --- | --- | --- |
| OpenAI | `OPENAI_API_KEY` | 빠른 통역은 `gpt-realtime-translate` + WebRTC. 원고 참고 방식은 별도 음성 인식·텍스트 번역 사용 |
| Google | `GOOGLE_API_KEY` (또는 `GEMINI_API_KEY`) | `gemini-3.5-live-translate-preview` + Gemini Live API v1beta WebSocket. 서버에서 1회용 단기 토큰 발급 |
| Microsoft Azure | `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION` | 브라우저 Speech SDK 연속 번역. 서버가 단기 토큰을 발급하고 8분마다 갱신 |

Microsoft에는 **Speech** 리소스가 필요합니다. 텍스트 Translator 키와 혼동하지 마세요. 리전은 리소스가 실제 배포된 값(예: `koreacentral`)을 사용합니다. 현재 Azure 구현은 일반 퍼블릭 클라우드의 **리전 엔드포인트** 기준이며 사설 엔드포인트·Entra 인증은 구현하지 않았습니다.

OpenAI 빠른 통역과 Google은 입력 언어를 자동 인식합니다. OpenAI의 설교 정확도·세미나 방식과 Microsoft에서는 선택한 ‘말하는 언어’를 음성 인식 설정에 반영합니다. 모델 접근 권한과 언어 지원은 계정 및 서비스에서 확인해야 합니다. OpenAI 빠른 통역 서비스가 반환하는 음성은 재생하지 않지만, 음성 출력의 생성·과금이 없어지는 것은 아닙니다.

### OpenAI 설정

1. [OpenAI Platform](https://platform.openai.com/)에 로그인하고 사용할 프로젝트를 선택합니다. [API Keys](https://platform.openai.com/api-keys)에서 API 키를 생성합니다. 발급 절차는 [공식 OpenAI 시작 안내](https://developers.openai.com/api/docs/quickstart#create-and-export-an-api-key)를 참고하세요.
2. 프로젝트의 API 사용을 위한 결제·사용 한도와 필요한 모델의 접근 권한을 확인합니다. 앱의 ‘설정됨’ 표시는 키 입력 여부만 확인하며, 실제 연결 성공을 보장하지 않습니다.
3. 프로젝트 폴더의 `.env`에서 아래 항목을 입력하거나 수정합니다. 같은 변수 이름을 여러 번 추가하지 말고 기존 값을 바꾸세요. 실제 키는 `.env.example`이나 GitHub에 넣지 않습니다.

```dotenv
OPENAI_API_KEY=발급받은_API_키
# 빠른 통역 모델 · 선택 항목, 생략 시 아래 모델 사용
OPENAI_TRANSLATION_MODEL=gpt-realtime-translate
# 설교 정확도·세미나 텍스트 번역 모델 · 선택 항목
OPENAI_SERMON_TEXT_MODEL=gpt-5.4-mini-2026-03-17
```

4. 처음 실행한다면 `npm run dev`로 서버를 시작합니다. 이미 실행 중이고 키·모델 설정만 바꿨다면 **연결 설정 → 설정 다시 확인**을 누릅니다. 진행 중인 통역은 종료하고 새 연결을 시작해야 변경된 값이 적용됩니다.
5. **OpenAI Realtime**을 선택하고 말하는 언어·번역 언어·오디오 입력을 정합니다. **통역 방식**에서 빠른 통역, 설교 정확도, 세미나-원고제공방식 중 원하는 방식을 선택한 뒤 **통역 시작**을 누르고 마이크 권한을 허용합니다.

세 방식은 같은 `OPENAI_API_KEY`를 사용합니다. 빠른 통역에는 `gpt-realtime-translate` 접근 권한이 필요하며, 설교 정확도·세미나 방식에는 `gpt-live-transcribe` 음성 인식과 설정된 Responses 텍스트 모델의 접근 권한이 필요합니다. `OPENAI_TRANSLATION_MODEL`은 빠른 통역에만, `OPENAI_SERMON_TEXT_MODEL`은 원고 참고 방식의 텍스트 번역에만 적용됩니다. 모델 이름은 이 앱의 기본값이므로 임의로 다른 모델을 입력하면 API 호환성 오류가 날 수 있습니다.

연결 실패 시에는 키가 올바른 프로젝트의 유효한 키인지, API 사용 한도·잔액과 모델 접근 권한이 있는지 확인하세요. 변수 이름은 **`OPENAI_API_KEY`**이며 `OPEN_API_KEY`가 아닙니다. 원고 참고 방식의 준비 절차는 아래 [세미나 사용법](#세미나-원고제공방식)을 참고하세요.

### Google 설정

1. [Google AI Studio](https://aistudio.google.com/apikey)에서 **Gemini API용 키**를 발급합니다. Cloud Speech-to-Text 전용 인증을 사용하는 방식이 아닙니다.
2. 기존 `.env`의 다른 키는 그대로 두고 아래 항목을 추가합니다. 실제 키를 채팅에 붙여 넣지 마세요.

```dotenv
GOOGLE_API_KEY=발급받은_키
# 선택 항목 (생략하면 아래 모델 사용)
GOOGLE_TRANSLATION_MODEL=gemini-3.5-live-translate-preview
```

3. 업데이트된 서버를 실행하고 화면을 새로고침한 다음 ‘연결 설정 → 설정 다시 확인’을 누릅니다. 이후 키 변경만 할 때에는 서버 재시작 없이 재확인이 가능합니다.
4. ‘Google · Live Translate’를 선택한 뒤 ‘통역 시작’을 누릅니다.

기존 `GEMINI_API_KEY`도 지원하며 두 변수가 모두 비어 있지 않으면 `GOOGLE_API_KEY`를 우선합니다. 프리뷰 모델의 계정·지역별 접근 권한과 결제·사용 한도를 확인해야 합니다. Google도 입력 언어를 자동 인식하며, 중국어 출력 선택은 `zh-Hans`로 전송합니다.

Google 키는 서버의 공식 Google Gen AI SDK에서만 사용합니다. 브라우저에는 번역 모델·출력 언어·원문/번역 수신 설정이 고정된 단기 토큰만 전달합니다(새 연결 시작 1분 이내, 토큰 최대 30분, 최초 사용 1회). 이 토큰 자체도 자격 증명이므로 개발자 도구·네트워크 로그를 공유하지 마세요. 마이크는 AudioWorklet으로 16 kHz 모노 PCM16, 100 ms 단위로 전송합니다. 음성 출력은 재생하지 않고 자막만 표시하지만 API의 음성 생성·과금까지 제거되는 것은 아닙니다.

**Google 연결 제한:** 현재 자동 세션 재개는 구현하지 않았습니다. Google이 연결 종료 예고(`goAway`)를 보내면 화면에 알리고, 연결이 종료되면 마이크를 해제합니다. 서비스의 연결 시간 제한이 토큰 유효기간보다 짧을 수 있으므로 긴 설교·강의에서는 제한 발생 시 통역을 다시 시작해야 합니다. 종료 때에는 남은 오디오를 전송하고 마지막 자막을 최대 5초간 기다립니다. 장시간 연속 운영과 실제 언어쌍 품질은 현장 테스트가 필요합니다.

### Microsoft Azure Speech 설정

1. [Azure Portal](https://portal.azure.com/)에 로그인하고 사용할 Azure 구독을 선택합니다. **Speech(음성)** 리소스를 생성합니다. 리소스 생성과 키 확인은 [Microsoft 음성 번역 시작 안내](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/get-started-speech-translation)를 참고하세요. 텍스트 전용 Translator 리소스의 키는 이 앱에서 사용하는 Speech 키와 다릅니다.
2. 생성한 Speech 리소스의 **키 및 엔드포인트(Keys and Endpoint)**에서 키와 리전(지역)을 확인합니다. 리전은 반드시 해당 키가 속한 리소스의 실제 값이어야 합니다.
3. 프로젝트 폴더의 `.env`에서 아래 두 값을 입력하거나 수정합니다. 기존 OpenAI·Google 설정은 유지해도 됩니다.

```dotenv
AZURE_SPEECH_KEY=발급받은_Speech_리소스_키
# 예시입니다. 실제 Speech 리소스의 리전으로 바꾸세요.
AZURE_SPEECH_REGION=koreacentral
```

4. 처음에는 `npm run dev`로 서버를 실행합니다. 실행 중 키·리전만 변경했다면 **연결 설정 → 설정 다시 확인**을 누르고 통역을 새로 시작합니다.
5. **Microsoft Azure Speech**를 선택하고 **말하는 언어**, **번역 언어**, **오디오 입력**을 정합니다. **통역 시작**을 누른 뒤 마이크 권한을 허용하고 원문·번역 자막을 확인합니다. 말하는 언어는 실제 발표자의 언어와 맞추세요.

이 앱은 `AZURE_SPEECH_KEY`와 `AZURE_SPEECH_REGION`으로 지역별 엔드포인트를 구성하므로 엔드포인트 URL을 별도로 입력하지 않습니다. `AZURE_SPEECH_REGION`에는 `https://...` 주소나 지역의 한글 이름 대신 `koreacentral` 같은 리전 코드를 넣습니다. Microsoft 예제의 `SPEECH_KEY`와 달리 **이 앱의 변수 이름은 `AZURE_SPEECH_KEY`**입니다.

키·리전 조합이 맞지 않거나 Speech 리소스가 아닌 키를 사용하면 연결에 실패할 수 있습니다. 구독 상태·할당량과 선택 언어 지원도 확인하세요. 현재 Azure 경로는 빠른 통역용이며, OpenAI 전용인 원고·용어집 참고 기능은 적용되지 않습니다. 리전 엔드포인트 기반의 퍼블릭 Azure만 지원하며 Entra ID·사설 엔드포인트 설정은 구현하지 않았습니다.

## 현장 사용

1. PC에 마이크 또는 교회 음향 믹서의 오디오 출력을 오디오 인터페이스로 연결합니다.
2. PC의 입력 장치를 확인하고 앱의 ‘오디오 입력’에서 선택합니다. 처음 권한을 허용하면 장치 이름이 표시됩니다.
3. 세션 이름, 서비스, 말하는 언어와 번역 언어를 선택합니다. 기본값은 한국어 → 영어입니다.
4. ‘자막 창 열기’를 누르고 새 창을 보조 화면으로 옮겨 전체화면 버튼을 누릅니다.
5. ‘통역 시작’ 후 마이크 권한을 허용합니다. 입력 레벨과 실제 번역을 확인합니다.
6. ‘번역어만’ 또는 ‘원어 + 번역어’를 선택합니다. 운영자 화면과 자막 창 양쪽에서 변경할 수 있고 서로 동기화됩니다. 최대 글자 크기를 조절할 수 있으며 긴 문장은 영역 안에 맞춰 자동 축소됩니다. ‘자막 잠시 숨기기’는 청중 표시만 숨기며 인식은 계속합니다. 입력 일시정지 버튼은 오디오 입력을 멈추지만 연결은 유지합니다.
7. ‘통역 종료’로 마지막 결과를 수신한 뒤 ‘기록 내려받기’로 Markdown 파일을 저장합니다.

입력 일시정지 중에도 공급자 세션은 유지되므로 비용이 반드시 중단되는 것은 아닙니다. 긴 휴식에는 통역 종료를 사용하세요. 재시작하면 새 기록이 만들어집니다.

### 설교 정확도 모드 — 원고·설교자 사전 참고

기존 빠른 통역과 별도로, **OpenAI를 선택한 뒤 ‘통역 방식 → 설교 정확도 · 원고·사전 참고’**를 선택합니다. Microsoft/Google 빠른 통역에는 아래 참고 자료가 적용되지 않습니다. 이 버전은 서버 API가 추가되었으므로 기존 서버를 종료하고 `npm run dev`로 다시 실행한 뒤 화면을 새로고침해야 합니다. 새로고침 전에 진행 중인 통역을 종료하고 기록을 내려받으세요.

1. 설교자 이름, 인식 어휘(줄마다 한 개, 최대 100개), 용어·문장별 선호 번역, 표현 주의사항을 등록합니다. 사전 언어와 실제 통역 언어가 일치해야 합니다.
2. ‘이 브라우저에 저장’을 누르면 설교자 사전만 localStorage에 저장합니다(최대 20개). 같은 이름·언어는 갱신됩니다. 파일로 보관하려면 ‘JSON 사전 내려받기’를 사용하세요. 파일을 다시 읽으려면 **‘저장된 사전’ 선택란 옆 ‘JSON 사전 불러오기’**에서 Between이 내보낸 UTF-8 JSON 파일(최대 60KB)을 선택합니다. 이름·언어·어휘·선호 번역·주의사항이 입력란에 반영되고 파일명이 표시됩니다. 확인 후 **‘사전 목록에 저장’**을 눌러야 다음에도 저장된 사전 목록에서 선택할 수 있습니다. 불러오기만으로 저장된 사전을 덮어쓰지 않으며, 파일 형식이 잘못되면 현재 편집 내용도 유지합니다. 공용 PC에서는 사용 후 저장 사전을 삭제하세요. 자동 음성 학습이나 모델 재학습은 하지 않습니다.
3. 그날 원고를 PDF 또는 UTF-8 `.txt`/`.md` 파일로 읽거나 직접 붙여넣습니다(텍스트 최대 320KB, PDF 최대 30MB·200쪽, 추출 원문 최대 80,000자). PDF는 브라우저에서 텍스트를 추출합니다. 스캔 PDF는 OCR로 변환해야 하며 Word·HWP는 PDF나 텍스트로 변환하여 입력하세요. 원고는 이 탭에만 유지되며 사전 저장에 포함하지 않습니다.
4. 성경 본문과 선호 번역본을 입력합니다. 선택 사항으로 직접 검토하고 사용할 권한이 있는 성경 원문·번역문도 등록할 수 있습니다. 번역본 이름만으로 정확한 인용문을 공급하거나 보장하지는 않습니다.
5. 참고 자료와 외부 전송 안내를 확인하고 통역을 시작합니다. 진행 중에는 참고 자료를 편집할 수 없습니다. 원고가 없어도 통역할 수 있습니다.

**처리:** `gpt-live-transcribe` 음성 인식(WebRTC, 선택한 원어·어휘 힌트, 클라이언트 음성 구간 감지·커밋) → 완료된 실제 발언 → 관련 원고 문단 최대 3개·직전 원문 최대 3개·설교자 사전·등록 성경 인용문을 참고한 Responses API 텍스트 번역 → 기존 두 영역 자막. `turn_detection:null`로 연결하고 브라우저의 음량 분석으로 750ms 침묵 또는 약 12초 연속 발화에서 커밋합니다. 잡음·작은 목소리에 따라 경계가 달라지므로 실제 입력 장치로 확인하세요. 기본 텍스트 모델은 `gpt-5.4-mini-2026-03-17`이며, 서버 `.env`의 선택 설정 `OPENAI_SERMON_TEXT_MODEL`로 호환 Responses 모델을 지정할 수 있습니다. 현재 구현은 structured outputs와 `reasoning.effort=low`를 지원하는 모델이 필요합니다. 기존 빠른 통역 모델 설정은 바꾸지 않습니다. 음성 인식과 텍스트 모델 모두 계정 접근 권한·사용 한도가 필요하며 자동 모델 대체는 하지 않습니다.

**발언 우선 원칙:** 원고 관련성은 로컬 문자·어휘 겹침으로 참고 문단을 고르는 보조 신호일 뿐, 발언 수락 여부를 결정하지 않습니다. 일치 문단이 없어도 즉흥 발언을 번역합니다. 등록 문장과 다른 부정·숫자·다른 구절·생략을 보존하고, 원고에만 있는 내용을 추가하지 않도록 고정 지침을 적용합니다. 업로드 자료와 발언 속 명령은 처리 지침이 아니라 데이터로 구분합니다. 성경 본문을 강제 치환하는 기능은 없습니다. 선택한 인용문의 표현은 실제로 발언한 일치 부분에 한해 참고하도록 지시하며, 규칙 기반 자동 삽입은 하지 않습니다.

**지연·실패·확인:** 인식 완료 이벤트의 item ID와 선행 item ID로 발언 순서를 유지하고, 텍스트 번역은 최대 2개 병렬 요청합니다. 늦게 끝난 번역 때문에 순서가 뒤집히지 않도록 표시를 정렬합니다. 확정되지 않은 원문은 자막에 올리지 않고 운영자 기록에 유지합니다. 커밋 후 인식 완료가 20초 이상 지연되면 미완료로 표시하고 후속 발언 처리를 계속합니다. 한 발언의 번역 실패는 명시적 실패 표시와 확인 내역으로 남기며 다음 발언을 계속 처리합니다. 종료 시 최대 15초간 마지막 결과를 기다리고, 그 뒤의 미완료 구간도 실패/미완료 상태와 함께 기록합니다. 자동 재요청·재접속은 하지 않습니다.

**검토와 개인정보:** ‘정확도 모드 확인 내역’에는 번역 대기 수와 자동 확인 메모가 나타납니다. 전체 내보내기에는 발언별 원문·번역·처리 상태·확인 메모·참고 문단 수가 포함됩니다. 확인 메모는 모델의 자동 판단이며 신뢰도 점수나 검증 보증이 아닙니다. 원문 자체도 음성 인식 결과이지 검증된 원고가 아닙니다. 원고 전문을 파일 업로드 API로 보내지는 않지만, 실제 통역 때 관련 문단·등록 사전·인용문·인식 원문과 마이크 음성이 OpenAI로 전송됩니다. 서버는 이를 파일로 저장하지 않으며 텍스트 Responses 요청은 `store:false`입니다. 공급자 측 데이터 처리 정책까지 로컬 설정으로 보장하는 것은 아닙니다. 장기 API 키는 서버에만 유지합니다.

이 모드는 별도 음성 인식·문맥 번역으로 비용과 지연이 추가될 수 있고 오류를 없애지는 못합니다. ‘마이크 없이 데모 체험’은 기존 고정 자막 시연이며 참고 자료를 적용하거나 실제 번역 품질을 검증하지 않습니다. 현장 적용 전 대표 설교 음성과 사람이 확인한 원문으로 성경 장·절, 물과 불, 부정 표현, 즉흥 발언, 마지막 발언의 보존과 지연을 비교하세요.

공식 문서: [실시간 음성 인식과 문맥 힌트](https://developers.openai.com/api/docs/guides/realtime-transcription), [WebRTC 연결](https://developers.openai.com/api/docs/guides/realtime-webrtc), [텍스트 생성 지침](https://developers.openai.com/api/docs/guides/text), [구조화 출력](https://developers.openai.com/api/docs/guides/structured-outputs). 공식 문서의 지원 범위에 따라 기존 직접 통역에 원고를 붙이는 대신 별도 인식·번역 경로로 구현했습니다.

### 세미나-원고제공방식

화면의 **‘세미나-원고제공방식’**에서는 발표 내용이 달라져도 프로그램을 변경할 필요 없이 원고와 용어집을 바꾸어 사용합니다. 아래 안내는 원고 구간을 지정해 통역하는 준비·운영 과정을 설명합니다.

**OpenAI → 통역 방식 → 세미나-원고제공방식**을 선택합니다. 기존 두 방식과 별도의 자료를 사용하며 특정 발표 내용에 고정되지 않습니다. 업데이트 후 서버를 재시작하고 운영자·청중 창을 새로고침하세요. 진행 중인 기록과 준비 자료는 먼저 내려받으세요.

1. PDF / UTF-8 TXT / Markdown 원고를 불러옵니다. PDF 최대 30MB·200쪽, 텍스트 최대 320KB, 추출 원문 총 80,000자·최대 300구간입니다. PDF는 브라우저 안에서 읽으며 원본 파일을 서버나 OpenAI에 업로드하지 않습니다. 이미지의 글자 인식(OCR)·사진 해석은 지원하지 않습니다. 암호 PDF는 해제 후 사용하세요. 글자가 없는 쪽은 안내하며 기존 자료는 읽기에 성공한 뒤 교체합니다.
2. 추출된 구간의 원문·제목·종류(발표 본문 / 표·사진 설명 등 참고 자료)를 확인합니다. PDF 쪽 번호는 유지하지만 PPT 슬라이드는 자동으로 추정하지 않으므로 직접 입력합니다. 표의 행·열, 수치·단위, 사진 설명과 본문 읽기 순서를 검토하세요. 구간을 추가하거나 삭제할 수 있습니다.
3. 발표자, 인식 어휘, 용어별 선호 번역을 입력합니다. 구간 번역을 직접 입력하거나 외부 전송·비용 안내를 체크한 뒤 **선택 구간 번역 초안 만들기**를 누릅니다. 초안은 사용자가 검토해야 합니다. 전체 원고를 자동 번역하거나 검토 번역을 발언 없이 그대로 자막에 내보내지 않습니다.
4. 원고 원어·번역어와 실제 통역 언어를 일치시킵니다. 원고 언어를 바꾸면 구간 번역·선호 번역을 비우고, 구간 원문을 수정하면 그 구간의 번역을 비웁니다. 현재 세미나 모드는 OpenAI의 기존 언어 제한을 따르며 라오어는 차단합니다.
5. 통역을 시작하고 **수동 고정 / 자동 추적 / 질의응답**을 선택합니다. 이전·다음 및 구간 선택은 통역 중에도 가능합니다. 자동 추적은 실제 발언의 어휘와 원고를 비교하는 보조 기능이며, 불확실하면 원고 없이 발언을 번역합니다. 문단 건너뛰기와 되돌아가기를 허용합니다. 질의응답에서는 원고·구간 번역을 보내지 않고 용어집과 최근 발언만 참고합니다.
6. **세미나 자료 내려받기**로 원고·구간 번역·용어집·슬라이드 연결을 JSON 파일에 보관합니다. **저장한 세미나 자료 불러오기**로 다음 발표에 재사용합니다. 브라우저 영구 저장은 하지 않으므로 탭 종료 전에 저장하세요. 실시간 통역 기록은 기존 Markdown 내보내기를 사용하며 참고한 구간 제목·PDF 쪽·슬라이드를 함께 기록합니다.

세미나도 실제 발언을 우선하며, 원고와 다른 숫자·부정·생략·즉흥 설명을 그대로 번역하도록 지시합니다. 원고의 지시문은 데이터로 처리합니다. 자료와 번역은 통역 시작 시 스냅샷으로 고정하며 진행 중에는 발표 위치만 바꿉니다. 음성·어휘·용어집·현재 참고 구간은 통역 중 OpenAI에 전송됩니다. 사전 번역과 실시간 인식·번역은 각각 API 비용이 발생할 수 있으며 정확도와 지연 개선은 실측이 필요합니다.

#### 준비 화면의 메뉴

**원고·용어집 준비**를 펼치면 다음 항목을 입력할 수 있습니다. 먼저 원고 원어·번역어를 정하고 번역과 용어집을 작성하세요. 한국어 발표를 영어로 통역한다면 원고 원어는 한국어, 원고 번역어는 영어이며, 상단 통역 설정도 한국어 → 영어로 맞춥니다.

| 메뉴 | 사용법 |
| --- | --- |
| 발표 원고 · PDF / TXT / Markdown | 원고 파일을 선택합니다. 읽기에 성공하면 기존 구간과 구간 번역을 교체합니다. 기존 발표자·용어집은 유지되므로 다른 발표 자료를 올렸다면 함께 검토하세요. |
| 자료 이름 | 자료를 구분할 이름입니다. 파일을 읽으면 파일명이 들어가며, `마나도 적정기술 세미나`처럼 수정할 수 있습니다. |
| 원고 원어 / 원고 번역어 | 원문 언어와 번역할 언어입니다. 둘 중 하나라도 변경하면 기존 구간 번역과 선호 번역이 비워집니다. |
| 발표자 | 발표자의 이름을 입력합니다. 참고 정보이며 목소리로 발표자를 식별하거나 학습하는 기능은 아닙니다. |
| 인식 어휘 | 잘못 알아듣기 쉬운 인명·지명·약어·전문 용어를 발표자가 말하는 언어로 입력합니다. 한 줄에 하나, 최대 100개입니다. |
| 용어·문장별 선호 번역 | 번역을 통일할 표현을 한 줄에 `원어 => 선호 번역` 형태로 입력합니다. |
| 표현의 의미·주의사항 | 표현의 의도, 혼동하기 쉬운 수치·대상 등 번역에 필요한 설명을 입력합니다. |
| 세미나 자료 내려받기 | 원고·구간 번역·용어집 등을 `between-seminar.json`으로 저장합니다. PDF나 통역 기록을 내려받는 버튼은 아닙니다. |
| 저장한 세미나 자료 불러오기 · JSON | 이 앱에서 내려받은 세미나 JSON 파일(최대 6MB)을 선택하여 준비 내용을 복원합니다. 현재 준비 자료를 교체합니다. |

#### 인식 어휘와 선호 번역의 구분

**인식 어휘는 ‘어떤 말로 받아쓸 것인가’, 선호 번역은 ‘어떤 표현으로 번역할 것인가’를 돕습니다.** 같은 용어를 양쪽에 넣어도 됩니다. 원고의 모든 단어 대신 인식하기 어렵거나 번역을 통일해야 하는 말을 등록하세요. 참고 정보이므로 정확한 인식이나 강제 치환을 보장하지는 않습니다.

한국어 → 영어 발표의 **인식 어휘** 입력 예:

```text
홍길동
마나도
바이오차
적정기술
```

같은 발표의 **용어·문장별 선호 번역** 입력 예:

```text
마나도 => Manado
바이오차 => biochar
적정기술 => appropriate technology
불을 설계한다 => design the combustion process
```

마지막 예처럼 의역이 필요한 문장은 발표 의도에 맞는지 검토한 뒤 등록하세요. 인명은 발표자가 실제 사용하는 영문 표기를 확인해 입력합니다. 번역 언어가 인도네시아어라면 선호 번역도 인도네시아어로 작성합니다.

**표현의 의미·주의사항** 입력 예:

```text
‘불을 설계한다’는 공기 공급과 연소 조건을 조절한다는 뜻입니다.
화로 내부 온도와 상판 온도는 서로 다른 측정값이므로 구분해 주세요.
```

#### PDF 추출 내용 확인과 구간 정리

1. **발표 원고**에서 PDF를 선택하고 구간을 불러왔다는 안내를 확인합니다. 텍스트 추출과 기본 구간 분리는 브라우저에서 수행합니다. AI가 전체 내용을 읽고 의미별로 재구성하는 전처리는 아닙니다.
2. PDF 쪽별 텍스트를 빈 줄과 길이를 기준으로 약 1,800자 단위로 나눕니다. 짧은 쪽은 한 구간, 긴 쪽은 여러 구간이 되며, 첫 줄을 기본 제목으로 사용합니다. PDF 쪽 번호를 보존하지만 발표 순서나 PPT 슬라이드 번호를 자동 판별하지는 않습니다.
3. **구간 선택**에서 확인할 항목을 고르고 **선택 구간 원문·번역 확인**을 펼칩니다. PDF 원본과 비교하여 누락·줄바꿈·표의 읽기 순서·숫자·단위를 확인하고 **구간 원문**을 수정합니다. 추출 원문에는 오탈자나 순서 오류가 있을 수 있습니다. 스캔 PDF는 외부에서 OCR을 거쳐 텍스트가 포함된 PDF로 준비해야 합니다.
4. **구간 제목**을 알아보기 쉽게 고치고 **연결할 PPT 슬라이드**를 직접 입력합니다. **구간 종류**는 말할 원고라면 ‘발표 본문’, 표·사진 설명 등 보조 정보라면 ‘표·사진 설명 등 참고 자료’로 지정합니다. 참고 자료도 번역 문맥에 사용될 수 있지만 말하지 않은 내용을 자막에 추가하도록 하는 설정은 아닙니다.
5. **구간 추가**는 맨 끝에 빈 구간을 만듭니다. 제목과 원문을 입력하고 필요 없는 항목은 **선택 구간 삭제**로 제거합니다. 빈 원문 구간이 남아 있으면 저장·통역 시작 검증을 통과하지 못합니다. 구간 원문은 최대 4,000자, 구간 번역은 최대 6,000자입니다.

현재 전용 **구간 분리·병합·순서 변경** 버튼은 없습니다. 구간을 나누려면 원문 일부를 새 구간에 복사한 뒤 기존 구간에서 삭제할 수 있지만, 새 구간은 맨 끝에 추가됩니다. 발표 중에는 구간 선택으로 원하는 위치를 직접 고를 수 있습니다. 원문을 수정하면 해당 구간의 번역이 비워지므로 원문 정리를 먼저 마치세요.

#### 구간 번역 준비와 저장

1. **구간 번역**에 검토한 번역을 직접 입력하거나, OpenAI 전송·API 비용 안내를 체크한 후 **선택 구간 번역 초안 만들기**를 누릅니다. OpenAI 서비스 설정이 필요합니다. 번역 초안 생성은 선택한 한 구간에만 적용됩니다.
2. 초안의 이름·전문 용어·숫자·단위·부정 표현을 확인하고 수정합니다. 구간 번역은 선택 사항이며 실제 통역에서 참고하는 자료입니다. 저장된 번역을 발언 없이 자동 재생하지 않습니다.
3. **세미나 자료 내려받기**로 JSON 파일을 저장하고 발표별로 파일명을 구분해 보관합니다. 다음에는 PDF 대신 **저장한 세미나 자료 불러오기 · JSON**을 사용하면 수정한 원문과 번역, 용어집을 함께 복원할 수 있습니다.

#### 발표 중 운영

원고 검토와 저장을 마친 뒤 오디오 입력·실제 통역 언어를 확인하고 **자막 창 열기 → 통역 시작** 순서로 진행합니다. 원고와 번역은 시작 시 고정되므로 내용을 수정하려면 통역을 종료한 뒤 편집하고 다시 시작하세요.

| 발표 위치 설정 | 사용하는 상황과 동작 |
| --- | --- |
| 수동 고정 | 기본 설정입니다. 운영자가 선택한 구간을 참고합니다. 발표 진행에 맞춰 ‘이전 구간’, ‘다음 구간’, ‘구간 선택’으로 이동하세요. |
| 자동 추적 | 실제 발언과 원고의 어휘 겹침으로 참고할 구간을 찾습니다. 건너뛰거나 앞 구간으로 돌아갈 수 있습니다. 일치가 불확실하면 원고 없이 발언을 번역합니다. 위치가 맞지 않으면 수동 고정으로 전환하세요. |
| 질의응답 · 원고 참고 끄기 | 원고와 구간 번역을 제외하고 실제 발언을 번역합니다. 용어집과 최근 발언은 계속 참고합니다. 발표를 재개하면 수동 고정이나 자동 추적으로 돌아갑니다. |

통역 중에도 발표 위치와 위 설정을 변경할 수 있습니다. 종료 후 **기록 내려받기**는 실제 발언과 번역을 Markdown으로 보관하는 기능이며, 준비 자료를 저장하는 **세미나 자료 내려받기**와 별개입니다. ‘마이크 없이 데모 체험’은 고정 예문을 보여주므로 업로드 원고의 추적이나 번역 품질을 시험하지는 않습니다.

구현 파일: `src/SeminarPanel.tsx`(준비·운영 화면), `src/manuscript.ts`(로컬 PDF 추출), `shared/seminar-context.mjs`(검증·구간 검색·번역 지침), `shared/speech-boundary.mjs`(음성 구간 감지). GET `/api/seminar/status`, POST `/api/seminar/translate`와 기존 음성 인식 토큰 경로를 사용합니다. PDF.js와 워커는 빌드에 포함하며 CDN에 원고를 전송하지 않습니다.

### 자막 화면의 두 영역

- **이전 자막(위쪽 약 ⅓)**: 현재 표시 구간 바로 앞의 최대 3문장.
- **현재 자막(넓은 약 ⅔)**: 인식이 완료된 원문과 도착한 번역, 각각 최대 3문장. 원문은 번역을 기다리지 않고 현재 영역에 반영합니다. 번역은 도착하는 대로 추가·갱신되며 스트리밍 중 마지막 미완성 번역 문장도 보입니다. 새 문장이 추가되면 오래된 문장이 위로 이동합니다.

별도의 ‘음성 인식 중’ 영역은 표시하지 않습니다. 미완료 원문은 내부 인식 처리와 운영자 실시간 기록에서 계속 관리하며, 해당 영역을 없애도 인식·번역·기록 처리에는 영향을 주지 않습니다. 운영자 자막 미리보기와 청중 창 모두 이전:현재 높이를 1:2로 배분합니다.

Azure는 `recognizing` 중간 결과를 내부에 유지하고 `recognized` 최종 결과를 받으면 현재 자막에 반영합니다. 데모도 인식 완료와 번역 도착을 분리하여 보여줍니다. 번역이 아직 없을 때는 완료 원문을 먼저 표시하고 번역 대기를 안내합니다.

Google의 `interimInputTranscription`은 내부의 임시 원문을 교체하며 전체 확정 원문에 누적하지 않습니다. `inputTranscription.finished=true`를 수신하면 해당 원문을 현재 자막에 반영합니다. 텍스트 없이 완료 신호만 도착해도 반영합니다. 명시적으로 `finished=false`를 받은 구간은 최종 신호를 기다립니다. 출력 번역의 완료(`turnComplete`)는 원문 인식 완료로 취급하지 않습니다.

**완료 신호가 없는 스트림:** OpenAI 통역 전용 API는 append-only 원문 delta를 제공하며 별도의 발화 완료 이벤트는 제공하지 않습니다. Google에서도 완료 플래그가 생략된 스트림은 같은 대체 규칙을 사용합니다. 언어별 문장 구분으로 앞 문장의 경계를 확인하면 현재 자막에 반영하고 ‘문장 구분 기준 원문’이라고 안내합니다. `。`, `!`, `?` 등의 끝 표시는 바로 반영하지만, 마지막 `.`만으로는 소수점·약어와 구별하기 어려워 다음 텍스트를 기다립니다. 이는 서비스가 보장하는 음성 인식 완료와 다릅니다. 문장 경계가 없는 마지막 원문은 중지·연결 끊김 때 억지로 완료 처리하지 않고 자막에는 표시하지 않으며, 수신된 전체 원문은 기록에 보존합니다.

원문과 번역문의 문장 수·도착 시점은 다르므로 번호·시간·수신 순서로 완료를 추정하지 않습니다. Google·OpenAI는 이전·현재 영역에 원어와 번역어의 별도 최신 구간을 표시하고 이를 화면에 안내합니다. Azure·데모는 번역이 함께 있는 발화는 발화 기준으로 표시하되 원문만 완료된 결과가 있으면 별도 구간으로 표시합니다. 한 발화가 여러 번역 문장에 걸치면 원문이 두 영역에 걸쳐 보일 수 있습니다. OpenAI 원문 수신 설정은 기존 `gpt-realtime-whisper`를 유지합니다.

이전·현재 영역의 완료된 원문과 번역문은 각각 문장마다 새 줄에서 시작하며 최대 3문장을 표시합니다. 원문·번역문을 문장 번호로 일대일 짝짓지는 않습니다. 긴 문장은 화면 너비에 따라 자동 줄바꿈되므로 ‘최대 3문장’은 ‘최대 3줄’과 다릅니다. 이 규칙은 운영자 미리보기와 청중 창에 동일하게 적용되며 기록 내보내기 내용은 변경하지 않습니다.

문장 구분은 언어별 문장 부호를 사용하며, 문장 부호가 없는 긴 발화는 한 문장으로 취급합니다. 매우 긴 문장이나 작은 화면에서는 최소 글자 크기를 유지하고 해당 영역에 스크롤·안내를 제공하여 내용을 자르지 않습니다. 전체 기록은 표시 영역과 무관하게 유지됩니다. 앱을 업데이트한 뒤에는 기록을 내려받고 운영자 화면과 자막 창을 모두 새로고침하세요.

## 범위와 현재 한계

- 한 번에 하나의 입력 스트림과 하나의 번역 언어를 사용합니다. 한국어, 영어, 일본어, 중국어, 스페인어, 프랑스어, 독일어, 베트남어, 라오어, 인도네시아어 선택 UI가 있습니다. 언어쌍의 실제 지원·품질은 서비스와 실측으로 확인해야 합니다.
- 청중 창은 `BroadcastChannel`로 **같은 브라우저·같은 origin·같은 PC**에서 연결됩니다. 청중 휴대폰에 QR 링크로 배포하는 기능은 아직 없습니다. `localhost`와 `127.0.0.1`도 서로 다른 origin입니다.
- 자막 창은 이전·현재의 2단 문장 창을 사용하며 전체 원문·번역은 운영자 기록에 유지됩니다. 원문·번역의 정확한 단어별 정렬이나 타임코드 자막(SRT/VTT)은 제공하지 않습니다.
- Azure 중간 결과는 수정될 수 있습니다. OpenAI는 수신한 텍스트 delta를 누적합니다. 종료 시 결과를 기다리지만 네트워크 단절이나 제한 시간 초과 시 마지막 일부 자막이 누락될 수 있습니다.
- 운영자 탭에서만 기록을 보관합니다. 서버나 localStorage에 음성·실시간 통역 기록·설교 원고를 저장하지 않습니다. 단, 명시적으로 저장한 설교자 어휘·표현 사전은 localStorage에 남습니다. 새로고침·탭 종료 전 필요한 기록을 내려받으세요. 마이크 오디오는 선택한 공급자에게 전송됩니다.
- 자동 재접속은 하지 않습니다. 연결 오류를 표시하고 입력을 해제합니다. 현장에서는 화면 상태를 확인하고 다시 시작할 수 있어야 합니다.
- 이번 구현 검증에서는 실제 마이크 음성과 유료 API를 사용하지 않았습니다. 성경 인명·지명·구절 번호·전문 용어와 발표 문맥은 실제 화자의 샘플로 확인해야 합니다. 원고·용어집은 OpenAI 설교 정확도·세미나 모드에서, 성경 번역본 참고는 설교 정확도 모드에서 적용합니다.
- 기본 서버는 `127.0.0.1`에서만 실행됩니다. 공개 배포 전에는 사용자 인증과 사용자별 사용량 제한이 필요합니다. `APP_ORIGIN`은 요청 출처 검사이며 사용자 인증을 대체하지 않습니다. 원격 마이크 사용에는 HTTPS가 필요합니다.

## 공유와 기여

오류 보고와 개선 제안은 [GitHub Issues](https://github.com/ai-space-s/realtime-translator/issues)에 남겨 주세요. 사용한 OS·브라우저, 통역 방식·언어, 재현 순서, 기대한 동작과 실제 동작을 알려주시면 도움이 됩니다. API 키, 인증 토큰, 개인 원고나 대화 기록은 게시하지 말고 공개 가능한 짧은 예문으로 재현해 주세요.

코드 변경은 별도 브랜치 또는 fork에서 작업한 뒤 Pull Request로 제안할 수 있습니다. `npm ci`, `npm test`, `npm run build`로 설치·자동 테스트·빌드를 확인하고, 사용법이 바뀌면 README도 함께 수정해 주세요. 자동 테스트와 고정 데모는 실제 마이크·유료 API의 번역 품질을 검증하지 않으므로 실제 서비스로 확인한 범위는 구분해서 적어 주세요.

`.env`, 설치된 `node_modules`, 빌드 결과 `dist`, 임시 폴더 `tmp`는 Git에 포함하지 않습니다. 개인 원고·음성·내보낸 통역 기록도 저장소에 추가하지 마세요. GitHub에 코드를 올리는 것만으로 실행 서버가 배포되지는 않습니다. 이 앱은 API 키를 보관하는 Node.js 서버가 필요하며 GitHub Pages만으로는 실행할 수 없습니다.
